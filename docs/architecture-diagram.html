Godwit

Privacy-first, local migration of email · calendar · contacts — any provider to any provider.

Named for the bird with the longest non-stop flight on record — carries everything across, intact.

Architecture overview · 2026-09-13

1. Hub-and-spoke connectors

One connector per provider — not one tool per pair. Add a provider once, it works with all of them, both directions.

2. A migration job — data flow

Streamed, checkpointed, idempotent, verified. Source is never deleted.

sequenceDiagram
    participant UI as UI (webview)
    participant Eng as Engine (Rust)
    participant Src as Source
    participant Dst as Destination
    UI->>Eng: Start (source, dest, scope)
    Eng->>Src: connect / list folders, calendars, contacts
    Eng->>Dst: connect / ensure targets exist
    loop per folder / calendar
      Eng->>Src: read items (stream, batched)
      Src-->>Eng: raw MIME / ICS / vCard
      Eng->>Dst: write (dedup by Message-ID / UID)
      Eng-->>UI: progress + counts
    end
    Eng->>Eng: verify counts, flags, structure
    Eng-->>UI: done + report

3. Components — all on the user's machine

The web UI can't open sockets, so all network I/O lives in the Rust core. Credentials stay in the OS keychain.
